Multi-band entry. One tap adds a row; the drag handle reorders billing (index 0 = headliner, matching the API 1:1 — no separate "who's headlining" picker). The first row is visually locked to the "Headliner" badge; every row below just renumbers as "2nd", "3rd"… on reorder. Typing a name either matches an existing Band (dedup happens server-side by normalized name) or creates one — the field doesn't need to know which. Progressive disclosure. Venue/price/times/note stay collapsed by default (phone, right) — jotting down a show is three taps: add band, pick date, save. The desktop mock (left) shows the section expanded to document every field it contains; collapsed is still the default state on both widths. Date picker. The calendar popover is the web/desktop control; on iOS/Android this same trigger opens the platform's native date picker instead (a modal wheel/calendar), so the field itself — icon, label, formatted value — is the only piece shared cross-platform. Timezone is a required API field (D-24: it drives the upcoming/past boundary) but isn't a field the user fills in — it's read from the device and shown as a small caption under the date, editable only if it's wrong (e.g. adding a show abroad after the fact); this keeps the fast path at zero extra taps for the common case.
