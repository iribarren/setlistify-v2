Why the stub only says "Upcoming"/"Past" here. The signature ticket card (design system, page 3) reserves its stub for playlist-match status — but that data doesn't exist until prompt 15+. Showing it here would be inventing state the API can't back. Once playlist generation ships, the stub's icon/label swap to the richer states already designed; the card's structure doesn't change. "boygenius + 2 more" is the truncation rule for a lineup that won't fit inline — full billing order is on the concert detail page. Grid is 3-up at 1440px, single column below ~900px (tablet breakpoint), matching the phone layout at right.
