Why the date locks on a past concert. Once a concert is past, editing the date to a future one would silently move it back to "upcoming," which is confusing given status is derived, not stored (D-24) — the UI just refuses to relitigate that boundary once it's crossed. Destructive action styling. The delete button is the only red UI in the whole design — reserved entirely for this one irreversible action, per the component inventory's destructive-button token. The confirmation always names the concert being deleted (band + venue + date), never a bare "Delete this?", since a user with several past shows shouldn't have to trust the tap alone.
