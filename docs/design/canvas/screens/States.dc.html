Setlistify — Concert Screens

07 · Loading, error & offline states

Concert list

loading — skeleton ticket cards, same 18px radius as the real card so nothing pops when content resolves

Couldn't load your concerts.
Try again

error — replaces the list area entirely; retry is the only action

You're offline — showing what's already synced

offline — cached concerts stay visible and interactive; only "Add concert" is disabled until reconnect

No past concerts yet

"filtered to zero" — the Past section when Upcoming has entries but Past doesn't; compact, inline, not the full-screen empty state

Concert detail

loading

This concert couldn't be found.
Back to concerts

error — includes the "not another user's concert" 404 case; the message never distinguishes "doesn't exist" from "not yours"

Couldn't save your changes — still offline

offline — editing while offline queues locally; a toast explains the change hasn't synced yet

Add / edit concert

Saving…

saving — the primary button becomes the only loading indicator; band/date fields lock while in flight

Couldn't reach setlist.fm to check that band name.

error — a band lookup failing doesn't block saving; typed names still save as free text and resolve later

You're offline — this will save once you're back online

offline — the form stays fully usable; save is queued rather than blocked, since jotting a concert down is exactly the moment connectivity is least reliable

General rule. Loading always uses skeletons shaped like the real content (never a spinner over blank space), so layout doesn't jump on resolve. Error always names what failed and offers exactly one recovery action. Offline never blocks reading what's already cached — Setlistify's whole premise is "jot it down in a hurry," so the add-concert flow in particular degrades to queue-and-sync rather than a hard stop.
