Five reasons, five sentences, zero error codes. Every row states a cause a non-technical person recognizes — a version choice, a rights gap, a data quirk from setlist.fm itself (the drum solo, the misattributed cover) — instead of "no match found." The row action always matches the reason: a version conflict offers "Pick a version," an outright absence offers "Skip" (with "Add anyway" for the misattribution case, since the real fix there is data, not matching). On phone, rows drop their action buttons and become tap targets instead — one row, one decision, no button crowding down a 5-item list; tapping opens the same picker inline. The list only ever shows the songs that need a look — matched songs don't appear here at all, so a 25-song setlist with 3 gaps is a 3-row screen, not a 25-row scroll.
